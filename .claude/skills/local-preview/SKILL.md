# 배포 전 로컬 미리보기

프론트엔드 화면을 바꿨으면 **배포 전에** 사용자가 직접 확인할 수 있도록 로컬 미리보기를 띄우고 두 링크를 준다.
배포는 여전히 사용자가 "배포해줘"라고 할 때만 한다.

## 미리보기가 하는 일 (preview/previewApi.ts)
- 로그인: 가짜 세션. `?role=admin` 관리자(전체 권한), `?role=user` 일반(일정 관리·투표 관리)
  - 카카오 로그인은 운영 주소로만 돌아오므로 로컬에서는 진짜 로그인을 쓸 수 없음
- 조회(GET): 운영 서버 데이터를 그대로 읽음. 로그인이 필요한 조회는 빈 결과로 대신함
  - 전체 회원 조회(`/user/get`)는 계정이 연결된 선수에게 **가짜 전화번호**를 붙여 돌려줌
- 저장·삭제(POST): 서버로 보내지 않음 → 운영 데이터는 바뀌지 않음 (새로고침하면 원래대로)
- 운영 빌드(`vite build`)에는 포함되지 않음 (`vite.preview.config.ts`에서만 src/api.ts를 바꿔 끼움)

## 절차
1. 타입 체크: 프론트엔드 폴더에서 `node node_modules/typescript/bin/tsc -b --noEmit`
2. 미리보기 서버가 꺼져 있으면 백그라운드로 실행 (포트 5174 고정, 이미 떠 있으면 코드 변경이 자동 반영됨)
   - 폴더: `C:\Users\jeong\OneDrive\바탕 화면\squrad-goalz\Squard-Goalz-fe`
   - 명령: `npm run preview:local`
   - 확인: `curl -s -o /dev/null -w "%{http_code}" "http://localhost:5174/?role=admin"` → 200
3. 가능하면 바뀐 화면을 헤드리스 크롬으로 폭 320 / 360 / 412px에서 찍어 넘침·깨짐을 확인
   - 탭 이동이 필요하면 같은 출처에서 iframe으로 여는 확인용 HTML을 `public/`에 잠시 두고, 확인 후 **반드시 삭제**
4. 사용자에게 두 링크를 준다
   - 관리자 버전: http://localhost:5174/?role=admin
   - 일반 버전: http://localhost:5174/?role=user
   - 어느 화면(탭)에서 무엇을 보면 되는지 함께 알려줌
   - 미리보기의 한계(가짜 로그인, 저장 안 됨, 로그인 필요한 데이터는 비어 보임, 카카오 공유 안 됨)를 필요한 만큼 알려줌
5. 사용자가 확인하고 "배포해줘"라고 하면 그때 커밋·푸시·배포

## 주의
- 미리보기 서버는 이 대화(세션)가 끝나면 꺼짐. 다음에는 `npm run preview:local`만 실행하면 같은 링크로 열림
- 새 API 경로를 추가했다면 미리보기도 `vite.config.ts` 프록시를 그대로 쓰므로 `vercel.json`과 `vite.config.ts` 둘 다에 등록해야 함
- 백엔드 변경이 함께 있는 경우: 미리보기는 **운영 서버**를 읽으므로, 아직 배포되지 않은 백엔드 API는 미리보기에서 동작하지 않음. 이 점을 사용자에게 알림
